### **1.1 游戏模块（`game/Game.java`）**
`Game` 类封装了应用程序的主要业务逻辑和农场机制。

**职责：**
- 跟踪每个农田地块的状态（`EMPTY`、`GROWING`、`RIPE`）。
- 管理种植、收获和偷窃操作。
- 包括持久化逻辑，用于保存和加载农场状态（例如，`toSaveString()`、`fromSaveString()`）。
- 使用 `ScheduledExecutorService` 控制作物生长异步计时器。

### **1.2 服务器模块（`server/Server.java`）**
`Server` 类实现了处理客户端连接和操作的后端服务器。

**职责：**
- 处理客户端命令（`LOGIN`、`GET`、`PLANT`、`HARVEST`、`STEAL` 等）。
- 使用 `client-io` 线程池管理客户端连接。
- 将农场状态持久化到磁盘（`farms.txt`），并在重启时重新加载。
- 向所有连接的客户端广播状态更新。

### **1.3 应用程序入口点（`Application.java`）**
`Application` 类作为 JavaFX 应用程序的入口点，并初始化 UI 组件。

**职责：**
- 显示登录窗口（`LoginWindow`）。
- 在成功登录后初始化 `Controller` 和 `Game`。
- 将客户端连接到服务器并处理会话设置。


### **1.4 并发测试（`ConcurrencyTest.java`）**
`ConcurrencyTest` 类是一个独立的测试套件，用于评估并发客户端操作下的服务器行为。

**职责：**
- 模拟多个客户端执行并发操作，如偷窃和种植。
- 使用 `CountDownLatch` 协调同时动作。
- 记录交互以调试竞态条件。


### **1.5 控制器模块（`Controller.java`）**
`Controller` 充当客户端 UI 和服务器逻辑之间的中介。

**职责：**
- 在游戏状态变化时更新 UI。
- 处理发送到服务器的命令（`STEAL`、`PLANT`、`HARVEST`）。
- 包括重新连接逻辑（`startReconnectLoop`），以维护无缝客户端体验。


### **1.6 登录窗口（`LoginWindow.java`）**
`LoginWindow` 类为应用程序提供初始登录 UI。

**职责：**
- 捕获用户的登录凭据，并将其传递给 `Controller`。
- 为无效输入显示错误消息（例如，空用户名）。
- 设置模态窗口以在登录成功前阻止交互。

### **1.7 系统架构特征**

1. **模块化设计**：
    - UI（`Controller`、`LoginWindow`）和业务逻辑（`Game`、`Server`）之间清晰分离。

2. **并发性**：
    - 线程池（`client-io`、`stats-monitor`）确保可扩展且响应迅速的操作跨多个客户端。

3. **持久性**：
    - 将农场状态保存到 `farms.txt` 以确保数据一致性跨系统崩溃或断开。

4. **错误恢复**：
    - 实现重新连接逻辑（`startReconnectLoop`）和用户友好的错误消息以处理断开连接。

## 3. 关键实现
此部分主要匹配项目描述 PDF 中的 **关键要求**。

### 3.1 服务器端实现
服务器管理所有玩家、作物生长和并发偷窃请求。它确保对共享数据（例如，作物产量）的更新是 **原子** 和 **线程安全的**。

#### 3.1.1 连接管理 ：
- **多线程架构**：使用 `CachedThreadPool` 为每个客户端连接生成一个线程。
- **ClientHandler**：每个连接的客户端由专用的 `client-io` 线程处理，该线程处理传入命令（LOGIN、PLANT、HARVEST、STEAL 等）。
- **线程池配置**：
  ```java
  private final ExecutorService pool = Executors.newCachedThreadPool((Runnable runnable) -> {
      Thread t = new Thread(runnable, "client-io");
      t.setDaemon(true);
      return t;
  });
  ```
#### 3.1.2 游戏状态管理 ：
- 每个玩家的农场对象：每个玩家的农场存储在 `ConcurrentHashMap<String, Game>` 中。
- 4×4 网格：每个 `Game` 对象维护一个 `PlotState[][] board`，包含 16 个地块。
- 作物状态：`EMPTY`（可种植）、`GROWING`（成熟中）、`RIPE`（准备收获）。

#### 3.1.3 作物生长线程 ：
- 自动成熟：种植作物时，`ScheduledExecutorService` 安排任务在 10 秒后将状态从 `GROWING` 更改为 `RIPE`。
- 后台计时器：每个 `Game` 对象有自己的 `crop-growth` 线程：
  ```Java
    private final ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1, runnable -> {
    Thread thread = new Thread(runnable, "crop-growth");
    thread.setDaemon(true);
    return thread;
    });
  ```
- 基于时间戳的恢复：服务器重启时，`GROWING` 作物基于存储在 `farms.txt` 中的经过时间恢复倒计时。

#### 3.1.4 原子操作 ：
- 种植：
    - 同步检查：在种植前，服务器验证地块为空且玩家有足够硬币：
    ```Java
    public void plant(int row, int col) {
        Consumer<Game> callback;
        long plantTime = System.currentTimeMillis();
        synchronized (this) {
            if (board[row][col] != PlotState.EMPTY) {
                throw new IllegalStateException("Plot occupied");
            }
            if (coins < PLANT_COST) {
                throw new IllegalStateException("Not enough coins");
            }
            coins -= PLANT_COST;
            board[row][col] = PlotState.GROWING;
            plantTimestamps[row][col] = plantTime;
            System.out.println(Thread.currentThread().getName() + " PLANT (" + row + "," + col + ") at " + plantTime);
            callback = onStateChange;
        }
        if (callback != null) callback.accept(this);
        // 10秒后成熟
        scheduleRipen(row, col, GROW_TIME_MS);
    }
    ```
- 收获：
    - 原子产量收集：只有所有者可以收获 RIPE 作物。操作是同步的：
    ```Java
    public void harvest(int row, int col) {
        Consumer<Game> callback;
        synchronized (this) {
            if (board[row][col] != PlotState.RIPE) {
                throw new IllegalStateException("Crop not ripe");
            }
            board[row][col] = PlotState.EMPTY;
            plantTimestamps[row][col] = 0;
            coins += HARVEST_REWARD;
            System.out.println(Thread.currentThread().getName() + " HARVEST (" + row + "," + col + ")");
            callback = onStateChange;
        }
        if (callback != null) callback.accept(this);
    }
    ```
- 偷窃：
  偷窃逻辑在服务器上实现，以确保线程安全和原子操作，防止竞态条件和强制执行游戏规则。

    - `synchronized (victim)` 块保证了对受害者农场的原子访问，用于并发偷窃请求。这通过以下方式防止过度偷窃：
        - 确保 `currentRipe` 和 `maxSteal` 基于最新状态计算。
        - 允许一次只有一个窃贼修改受害者农场。

    - 使用单个锁（`synchronized (victim)`）就足够了，因为：
        - 受害者作物状态独立于窃贼硬币状态。
        - 窃贼硬币余额更新（`addCoins`）在 `Game` 类的内部同步处理，确保线程安全，而不扩展关键部分。

  ```Java
  private void handle(String line) {
        try { // ... other command handling ... 
             switch (cmd) { // ... 
                      case "STEAL": { // ...
                          synchronized (victim) {
                              int currentRipe = victim.getRipeCount();
                              int maxSteal = (int) (currentRipe * 0.25);
                              // ...
                              if (sessionCount >= maxSteal) {
                                  out.println("ERR Cannot steal more in this session");
                                  System.out.println("[STEAL] " + player + " failed - session limit reached, current: "
                                          + sessionCount + ", max: " + maxSteal);
                                  break;
                              }
                              boolean success = victim.stealOneRipe();
                              if (success) {
                                  thief.addCoins(Game.STEAL_REWARD);
                                  thiefSession.put(victimName, sessionCount + 1);
                                  out.println("OK " + snapshot(thief));
                                  System.out.println("[STEAL] " + player + " successfully stole from " + victimName
                                          + " | session count: " + (sessionCount + 1));
                                  if ((sessionCount + 1) >= maxSteal) {
                                      thiefCanSteal.put(victimName, false);
                                      System.out.println("[STEAL] " + player + " reached maxSteal for " + victimName + " in this session");
                                  }
                              } else {
                                  out.println("ERR No ripe crops to steal");
                                  System.out.println("[STEAL] " + player + " failed - no ripe crops in " + victimName + "'s farm");
                              }
                          }
                          // ...  
                      }
                      default:out.println("ERR Unknown command: " + cmd);
             }
        } catch (Exception e) {out.println("ERR " + e.getMessage());}
  }
  ```

#### 3.2.4 网络和更新 ：
- 异步网络由 `listenThread` 处理。线程监听服务器更新并相应处理。服务器推送通知实时处理。
  ```
  listenThread = new Thread(this::listenLoop, "server-listener");
  listenThread.setDaemon(true);
  listenThread.start();
  ```
- 推送通知：服务器每当农场更改时广播 UPDATE <player> <snapshot>。客户端监听该玩家的农场通过 `Platform.runLater()` 刷新 UI。
- 推送通知处理在 `listenThread` 中的 `listenLoop` 运行的异步方式。服务器更新被实时处理，并通过 `Platform.runLater()` 推迟 UI 更新。这允许应用程序在网络活动期间保持响应。
- 线程安全：所有 UI 更新必须在 JavaFX Application Thread 上进行：
  ```
  Platform.runLater(() -> {
  updateGameSnapshot(myFarmGame, json);
  refreshBoardFromGameState();
  });
  ```

#### 3.2.5 响应性 ：
- 无阻塞：长时间运行的任务（网络 I/O、作物计时器）脱离 JavaFX Application Thread。
- 时间线刻度：Timeline 每秒刷新网格以反映状态变化（例如，GROWING → RIPE）。
- 设计将所有网络相关任务移动到后台线程（`listenThread`），并使用 `Platform.runLater()` 进行安全 UI 更新。这确保了在网络活动期间的平滑交互和非阻塞 UI。
```java
private void listenLoop() {
    String line;
    try {
        while ((line = in.readLine()) != null) {
            final String msg = line;
            // ...
                Platform.runLater(() -> {
                    if (msg.startsWith("OK LOGGED_IN")) {
                        connected = true;
                        showStatus("Successfully connected to farm server!");
                        updateButtonStates();
                    } else if (msg.contains("{")) {
                        String json = msg.substring(3);
                        if (lastCommand.startsWith("STEAL")) {
                            updateGameSnapshot(myFarmGame, json);
                            updateCoinsDisplay();
                        } else if (lastCommand.startsWith("VIEW")) {
                            updateGameSnapshot(viewingFarmGame, json);
                            refreshBoardFromGameState();
                            updateCoinsDisplay();
                        } else if (lastCommand.startsWith("GET")) {
                            updateGameSnapshot(myFarmGame, json);
                            viewingFarmGame = myFarmGame;
                            viewingPlayerName = myPlayerName;
                            refreshBoardFromGameState();
                            updateCoinsDisplay();
                        } else if (lastCommand.startsWith("PLANT") || lastCommand.startsWith("HARVEST")) {
                            updateGameSnapshot(myFarmGame, json);
                            refreshBoardFromGameState();
                            updateCoinsDisplay();
                        } else {
                            if (viewingPlayerName.equals(myPlayerName)) {
                                updateGameSnapshot(myFarmGame, json);
                            } else {
                                updateGameSnapshot(viewingFarmGame, json);
                            }
                            refreshBoardFromGameState();
                            updateCoinsDisplay();
                        }
                    }
                    // ...
                });    
        }// ...
        Platform.runLater(this::onDisconnected);
    } catch (IOException e) {
        Platform.runLater(this::onDisconnected);
    }
}
```

### 3.4 并发和同步

#### 3.4.1 服务器端锁定
- 同步块：所有关键部分（种植、收获、偷窃）使用 `synchronized (this)` 以防止竞态条件。
- 仅受害者锁定：偷窃期间，只有受害者的 Game 对象被锁定，避免死锁。

#### 3.4.2 线程模型

- 确保后台生长计时器和网络处理器不会相互阻塞。

  关键点：
    1. `Game.scheduleRipen()` 中的作物成熟计时器进入同步块仅用于简短状态翻转（GROWING → RIPE），最小化锁持续时间。  
       → 生长任务获取微小锁仅更新一个地块并立即释放。
    2. 服务器上的网络命令处理在 `client-io` 线程中运行，每个处理器快速处理请求并返回；它不与其生长任务共享锁（除了每个农场（Game）同步的简短）。不同的 Game 实例隔离争用。  
       → 命令处理器和生长计时器独立运行。
    3. 客户端 UI 更新使用 `Platform.runLater()` 将工作返回到 JavaFX Application Thread，防止后台监听器线程直接触摸 UI 组件。  
       → UI 线程保持响应且从不阻塞 I/O 或计时器。
    4. 服务器统计报告和持久化（`saveFarmsToDisk()`）使用单独执行器，避免干扰实时游戏操作。  
       → 定期任务不长时间持有游戏锁且从不阻塞连接处理。

  通过结合非常短的同步部分、不同执行器（客户端 I/O、作物生长、统计）和通过 `Platform.runLater()` 的 UI 分派，设计确保生长计时器、网络处理器和 UI 渲染不会相互阻塞。这分离保留了并发活动下的响应性。

### 3.5 异常处理

#### 3.5.1 服务器崩溃 ：
优雅处理服务器崩溃或断开，用户通知。
- 客户端检测：listenLoop 捕获 IOException 当服务器断开时。
- 用户通知：UI 显示“从服务器断开。正在尝试重新连接...”。所有按钮变灰以指示它们无法使用。
- 自动重新连接：客户端最多重试连接 10 次（3 秒间隔）。
- 状态恢复：服务器重启时，从 farms.txt 加载并恢复所有农场状态（包括 GROWING 计时器）。
  ![img_10.png](img_10.png)

#### 3.5.2 用户输入验证 ：
验证用户输入（例如，不能在占用地块种植）。
- 不能在占用地块种植：服务器检查 if (board[row][col] != EMPTY) 并返回 ERR Plot occupied。
- 不能收获非 RIPE 作物：抛出 IllegalStateException("Crop not ripe")。
- 不能自己偷窃：ensure(!victimName.equals(player), "Cannot steal yourself")。

#### 3.5.3 网络 I/O 错误 ：
捕获网络 I/O 错误而不崩溃 UI。
- 优雅处理：所有套接字操作包装在 try-catch 块中。
- 无 UI 崩溃：异常记录到控制台；UI 保持功能并显示错误消息。

## 4. 自检

### 4.1 线程池和计时器 ：
此部分主要讨论线程池和计时器及其配置以及它们如何避免死锁。

- 线程池配置：
    - `pool` 用于网络操作。
        - **池**：使用 `Executors.newCachedThreadPool` 创建，根据任务需求动态扩展。
        - **线程命名**：线程有可识别名称如 `client-io`，启用调试。
        - **守护线程**：设置为守护状态以便它们不阻塞 JVM 退出。
    - `statsExecutor` 用于定期任务。
        - **StatsExecutor**：使用 `Executors.newScheduledThreadPool(1)` 创建，专为定期任务设计。
        - **单线程**：配置为一个线程以确保序列化任务执行。
- 死锁预防策略：
  确保通过适当锁定、线程隔离和顺序资源访问避免死锁。
    - **锁顺序**：同步一次应用于一个资源，避免嵌套锁。
    - **分离任务**：长时间运行的任务分配给 `pool`，防止 UI 冻结或阻塞主线程。
- Platform.runLater 用于 UI 更新：
  所有 UI 更新使用 `Platform.runLater()` 安全提交到 JavaFX Application Thread。
    - 确保线程安全：防止 UI 更新与后台线程竞争。
    - 保持 UI 响应：长时间任务从不直接与 JavaFX Application Thread 交互。


### 4.2 处理崩溃期间未发送动作 ：
此部分主要解释崩溃发生时如何处理未发送动作。

- 持久数据（例如，农场状态和玩家硬币）保存到磁盘，并在服务器重启时重新加载。
```java
private synchronized void saveFarmsToDisk() {
    try (PrintWriter pw = new PrintWriter(new OutputStreamWriter(new FileOutputStream(SAVE_FILE),(StandardCharsets.UTF_8)))) {
        for (var entry : farms.entrySet()) {
            String name = entry.getKey();
            Game g = entry.getValue();
            pw.println(name + " " + g.toSaveString());
        }
        pw.flush();
        log("PERSIST", "saved file=" + SAVE_FILE + " farms=" + farms.size());
    } catch (IOException ex) {
        log("PERSIST-ERR", "error=" + ex.getMessage());
    }
}
```
- 确保游戏关键数据在突兀崩溃或中断期间不丢失。
```java
public synchronized void fromSaveString(String saveStr) {
    long now = System.currentTimeMillis(); // 当前时间
    for (int r = 0; r < ROWS; r++) {
        for (int c = 0; c < COLS; c++) {
            long timestamp = Long.parseLong(tokens[idx + 1].trim()); // 恢复存储的时间戳
            if (state == PlotState.GROWING && now - timestamp < GROW_TIME_MS) {
                scheduleRipen(r, c, remainingTime); // 未成熟则再次倒计时
            } else {
                board[r][c] = PlotState.RIPE; // 超时直接成熟
            }
        }
    }
}
```

### 4.3 评估标准 ：
此部分总结代码覆盖的标准哪些部分（服务器逻辑、客户端 UI、并发、错误处理）。

| **类别**       | **重点领域**                                                                |
|---------------------|-------------------------------------------------------------------------------|
| **服务器**          | 线程安全、状态一致性和协议设计。                       |
| **客户端**          | 网络逻辑、响应性和可用性。                            |
| **GUI**             | 视觉清晰度、反馈线索和交互设计。                       |
| **并发**             | 竞态条件处理和同步操作。                         |
| **错误处理**        | 从客户端/服务器/网络失败的优雅恢复。                       |

#### 服务器：
- 实现同步访问控制农场操作如种植和偷窃，以确保线程安全。
- 将农场状态持久化在 `farms.txt` 中以保证状态一致性跨会话。
- 为清晰可靠的客户端-服务器交互设计通信协议（例如，`LOGIN`、`STEAL`、`PLANT`）。

#### 客户端：
- 提供无缝重新连接逻辑（`startReconnectLoop`）以处理网络中断。
- 即使在网络不稳定期间，确保动作如 `STEAL`、`PLANT` 和 `HARVEST` 显示即时反馈以增强响应性。
- 使用错误提示（例如，“从服务器断开”）以提高可用性。

#### GUI：
- 使用 JavaFX 设计为实时 UI 更新和交互反馈（例如，地块选择）。
- 动态显示游戏状态（硬币、作物状态）以实现视觉清晰度。
- 使用动画（例如，按钮颜色过渡）以改善用户体验。

#### 并发：
- 处理来自多个客户端的同时操作（例如，种植和偷窃）使用线程池（`client-io`）。
- 使用 `synchronized` 块同步共享资源（例如，偷窃动作期间锁定受害者农场）。
- 确保定时任务（例如，作物成熟）的干净执行，而无竞态条件。
- **服务器线程：**
    - `CachedThreadPool` 用于客户端 I/O。
    - `ScheduledExecutorService` 用于作物生长（每个 `Game` 一个）。
    - `ScheduledExecutorService` 用于服务器统计（每 60 秒）。
- **客户端线程：**
    - `server-listener` 线程用于异步消息接收。
    - `reconnect-loop` 线程用于自动重新连接。
    - JavaFX Application Thread 用于 UI 更新。
- **同步：**
    - `Game` 使用 `synchronized` 方法用于硬币、板状态。
    - `Server.STEAL` 使用 `synchronized(victim)` 以确保原子检查 + 扣除。
    - 回调（`onStateChange`）在同步块外调用以减少锁持有时间。
- **死锁避免：**
    - 偷窃期间只持有一次锁（受害者的 Game 对象）。
    - 通过 `Platform.runLater`（无锁持有）进行 UI 更新。
- **压力测试：**
    - `ConcurrencyTest.java` 模拟两个窃贼同时从一个受害者（4 个 RIPE 作物）偷窃。
    - 使用 `CountDownLatch` 用于同步开始。
    - 验证：第一个成功减少成熟 4→3，第二个请求看到 maxSteal=0 → 失败。

#### 错误处理：
- **客户端崩溃：**
    - 服务器在 `ClientHandler.finally` 中检测断开。
    - 清理 `allClients`、`currentView`、`sessionStealCounts`。
    - 农场状态保存在 `farms` 地图中。
    - 客户端可以重新启动，`LOGIN` 再次，并从保存状态恢复。
- **服务器崩溃：**
    - 客户端的 `listenLoop` 捕获 `IOException` → `onDisconnected()`。
    - UI 显示“从服务器断开。正在尝试重新连接...”。
    - 所有动作按钮禁用（`updateButtonStates()`）。
    - `startReconnectLoop()` 重试连接最多 10 次，3 秒间隔。
    - 成功时：`LOGIN` + `GET` → 从磁盘恢复农场状态。
- **未发送动作：**
    - 命令通过 `out.println()` 一次发送。
    - 如果连接中途下降，命令丢失（未排队）。
    - 客户端在重新连接时与服务器的权威状态重新同步。
- **输入验证：**
    - `ensure()` 检查命令格式、坐标和玩家状态。
    - 在 `handle()` 中捕获异常 → 发送 `ERR` 消息到客户端。


### 4.4 讨论点 ：

#### 4.4.1 数据一致性保证 数据一致性保证 ：
1. **同步农场状态**：
    - 在操作期间（例如，偷窃、种植），同步块应用于确保一次只有一个线程可以修改农场状态。 使用同步块，确保一次只有一个线程可以修改农场状态
    - 例如，偷窃逻辑中的 `synchronized (victim)`。

2. **持久存储**：
    - 农场状态（例如，硬币、地块状态）定期保存到文件（`farms.txt`）使用 `Server.java` 中的 `saveFarmsToDisk()` 方法。
    - 如果系统崩溃，数据使用 `loadFarmsFromDisk()` 方法重新加载。

3. **实时同步**：
    - 客户端农场更新立即广播到其他玩家使用 `broadcastUpdate()` 方法，确保跨所有玩家的视图一致。


#### 4.4.2 线程同步选择 线程同步选择 ：
1. **同步块**：
    - 应用于共享资源如农场状态（例如，`synchronized(victim)`）。
    - 确保线程安全而不死锁，因为未使用嵌套锁。

2. **线程池**：
    - 使用 `client-io` 线程池用于异步处理 `STEAL` 请求等网络相关操作。
    - `stats-monitor` 线程池处理服务器监控定期任务。

3. **最小化关键部分**：
    - 确保只有操作的关键部分同步化，如偷窃期间更新农场状态。


#### 4.4.3 系统扩展机会 系统扩展机会 ：
1. **全局排行榜**：
    - 添加显示基于硬币或整体农场生产力的顶级玩家的排行榜。

2. **增强农场机制**：
    - 引入新游戏玩法如玩家之间交易作物或协作耕作。
    - 实施不同作物类型，具有不同生长时间和奖励。
    - 使用赚取的硬币购买农场升级或装饰。
    - 除了种植植物之外，允许玩家饲养动物（例如，鸡、牛）或钓鱼以随时间产生资源。

3. **安全增强**：
    - 为安全客户端-服务器交互实施加密或用户认证。

4. **实时事件调度**：
    - 引入特殊事件（例如，作物节日或竞赛）以提高参与度。


## 5. 协议描述

项目的客户端和服务器之间的通信协议基于简单的 **命令驱动交互**。命令从客户端发送为纯文本字符串，响应作为纯文本返回。以下描述代码中实现的协议。


### **5.1 LOGIN**
- **描述：** 使用服务器注册新玩家或重新连接现有玩家。
- **命令格式：** `LOGIN <playerName>`
    - 示例：`LOGIN alice`
- **服务器动作：**
    - 创建或获取玩家的农场对象。
    - 初始化玩家的会话。
- **响应格式：** `OK LOGGED_IN <playerName>`


### **5.2 GET**
- **描述：** 检索玩家自己农场的当前状态。
- **命令格式：** `GET`
- **服务器动作：**
    - 返回包括地块信息和硬币的农场状态。
- **响应格式：** `OK {"coins":40,"board":[["EMPTY","RIPE"],...]}`


### **5.3 VIEW**
- **描述：** 检索另一个玩家的农场状态。
- **命令格式：** `VIEW <playerName>`
    - 示例：`VIEW bob`
- **服务器动作：**
    - 返回请求玩家的农场状态。
- **响应格式：** `OK {"coins":20,"board":[["GROWING","EMPTY"],...]}`


### **5.4 PLANT**
- **描述：** 在玩家农场的指定地块种植作物。
- **命令格式：** `PLANT <row> <column>`
    - **示例：** `PLANT 1 2`
- **服务器动作：**
    - 将指定地块更新为 `GROWING`。
    - 从玩家扣除硬币。
- **响应格式：** `OK PLANTED at (1,2)`


### **5.5 HARVEST**
- **描述：** 从玩家农场的指定地块收获作物。
- **命令格式：** `HARVEST <row> <column>`
    - 示例：`HARVEST 0 3`
- **服务器动作：**
    - 将指定地块更新为 `EMPTY`。
    - 添加硬币到玩家的余额。
- **响应格式：** `OK HARVESTED at (0,3)`


### **5.6 STEAL**
- **描述：** 尝试从另一个玩家的农场偷取一个成熟作物。
- **命令格式：** `STEAL <playerName>`
    - 示例：`STEAL bob`
- **服务器动作：**
    - 锁定受害者农场以防止并发更改。
    - 如果可用，转移一个成熟作物（如果可用）到窃贼农场。
- **响应格式：** `OK STEAL successful` 或 `ERR No ripe crops`
