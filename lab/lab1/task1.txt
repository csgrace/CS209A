问题：
Reflect: Compare your findings with the AI's explanation. Why does the JVM need to load so many classes just to run a simple program?
回答：
JVM 之所以需要加载这么多类，是因为 Java 平台本身设计为高度模块化和通用。JVM 启动时不仅仅是加载用户的主类（如 Example1），而是要逐步搭建起一个完整的运行时环境。
具体原因包括：
1. 基础依赖层层递进：  
   Java 的核心类型（如 Object、Class、String、Thread、Exception 等）是所有程序的基础。没有这些，连最简单的对象创建、类型判断或者异常处理都无法进行。  
2. 安全与模块体系初始化：  
   JVM 要保证类的加载和执行都发生在受控、安全的环境下，所以早期就要加载大量与安全、权限、模块系统有关的类。这为后续所有应用代码提供了隔离和保护。
3. 反射与动态特性：  
   现代 Java 应用（包括许多底层库）广泛使用反射和动态语言特性。这些需要 JVM 额外加载反射相关的类，为后续动态调用和框架支持打基础。
4. 工具类与集合框架：  
   即使用户代码很简单，底层如 System.out.println 也可能用到集合、工具类等。这些都是标准库中必不可少的部分。
5. I/O 与字符集支持：  
   程序的输入输出会牵涉到字符集、流等大量标准库类。JVM 需要确保这些功能随时可用。
6. 类加载器与服务机制：  
   为了能灵活加载应用和第三方库，JVM 要先搭建好多层次的类加载器和服务发现机制。
7. 高效启动（CDS）：  
   现代 JVM 利用 CDS 机制，将常用类预先打包共享，虽然启动时看起来加载了很多类，但实际上极快且高效。

总结：  
JVM 不是为单一程序定制的“精简虚拟机”，而是为所有 Java 应用提供统一、稳定、安全的执行环境。即使是最小的 Java 程序，也会自动享有这些“重型”基础设施，正因如此，Java 应用才具有良好的可移植性、健壮性和扩展性。
